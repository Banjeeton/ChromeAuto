# Технический spike: Playwright CRX

Дата проверки: 27 сентября 2026 года.

## Цель

Проверить, можно ли использовать `playwright-crx` как движок автоматизации
в Manifest V3-расширении, которое управляет уже открытой вкладкой Chrome, а не
запускает отдельный браузер.

Spike отвечает на четыре вопроса:

1. можно ли подключиться к существующей вкладке по `tabId`;
2. доступны ли обычные операции Playwright, включая чтение страницы и reload;
3. собирается ли библиотека текущим инструментарием проекта;
4. можно ли изолировать библиотеку за адаптером, чтобы впоследствии заменить
   ее без изменения пресетов и доменной логики.

## Проверенное окружение

- Node.js 24 и npm 11;
- Manifest V3;
- установленный Chrome `153.0.8010.53`;
- `playwright-crx@0.15.0`;
- Vite `8.3.1`, затем Vite `7.3.6`;
- TypeScript 7 и Vitest 5.

`playwright-crx@0.15.0` — последний опубликованный релиз на момент spike. Он
основан на Playwright 1.53.0.

## Результаты

| Проверка | Результат |
| --- | --- |
| TypeScript API `crx.start()` и `application.attach(tabId)` | Пройдено |
| Изоляция библиотеки в адаптере | Пройдено |
| Повторное использование одной сессии для одного `tabId` | Пройдено unit-тестом |
| Получение `title` и `url` существующей вкладки | Реализовано, требуется ручная проверка в Chrome |
| Перезагрузка страницы через `page.reload()` | Реализовано, требуется ручная проверка в Chrome |
| Detach отдельной вкладки | Реализовано и покрыто unit-тестом |
| Сборка Vite 8 | Не пройдена |
| Сборка Vite 7.3.6 | Пройдена |
| Полный `npm run verify` | Пройден |
| Runtime-проверка в Chrome 153 | Не выполнялась: требуется ручная загрузка unpacked-расширения |

Собранный background service worker с Playwright CRX имеет размер примерно
3,03 МБ без gzip и 840 КБ с gzip. Source map занимает примерно 9,07 МБ, но он
нужен только для разработки.

## Реализованный PoC

Адаптер `PlaywrightEngine` находится в
`src/adapters/playwright/playwright-engine.ts`. Он:

- лениво запускает один экземпляр `CrxApplication`;
- подключает Playwright только к явно указанной вкладке;
- хранит независимую `Page` для каждого `tabId`;
- возвращает снимок `title` и `url`;
- перезагружает страницу с ожиданием `domcontentloaded`;
- отключает одну вкладку или закрывает весь экземпляр;
- очищает локальную сессию при событии `detached`.

В background service worker добавлен временный message endpoint:

```ts
type PlaywrightSpikeMessage = {
  type: "playwright-crx/spike";
  action: "snapshot" | "reload" | "detach";
  tabId: number;
};
```

Он предназначен только для проверки интеграции. В рабочей реализации его
заменит application service с командами запуска и остановки автоматизации.

## Обнаруженные ограничения

### 1. Требуется разрешение `debugger`

Playwright CRX работает поверх `chrome.debugger`, поэтому расширение обязано
объявить разрешение `debugger`. Chrome показывает пользователю заметное
предупреждение о доступе расширения к отладчику. Это допустимо для личного
unpacked-расширения, но разрешение должно использоваться только во время
активной автоматизации.

Открытие DevTools для вкладки или подключение другого debugger-клиента может
завершить сессию расширения. Событие detach нужно преобразовывать в понятную
ошибку запуска с указанием текущего шага.

### 2. Vite 8 несовместим с опубликованным пакетом

Сборка на Vite 8.3.1 завершается двумя ошибками из опубликованного bundle:

```text
Could not resolve '../playwright'
Could not resolve './bidiOverCdp'
```

Проблема воспроизводится в нашем проекте и отдельно зарегистрирована в issue
проекта Playwright CRX. На Vite 7.3.6 тот же код собирается. Для PoC Vite
закреплен на 7.3.6. Обновлять его до Vite 8 нельзя, пока upstream не выпустит
исправление либо мы не подготовим собственный fork.

### 3. Версия встроенного Playwright отстает от Chrome

Релиз `playwright-crx@0.15.0` опубликован 11 июня 2025 года и содержит
Playwright 1.53.0. В upstream открыт запрос на обновление для Chrome 146, тогда
как на машине разработки уже установлен Chrome 153. Успешная сборка поэтому
не доказывает runtime-совместимость.

### 4. Пакет нельзя импортировать в Node-тестах без изоляции

Во время импорта пакет обращается к browser global `self`. Unit-тесты адаптера
используют mock модуля, а реальные проверки должны выполняться в Chrome.

### 5. Жизненный цикл Manifest V3

Начиная с Chrome 118 активная сессия `chrome.debugger` удерживает service
worker активным. Поэтому минимальная версия Chrome повышена до 118. Состояние
пресета, текущего шага и журнала все равно нельзя хранить только в памяти:
браузер или расширение могут быть перезапущены.

Повторные запуски раз в N минут должны планироваться через `chrome.alarms`
после завершения предыдущего цикла. Таймер не должен жить внутри
`PlaywrightEngine`.

## Архитектурное решение

Статус: **условный GO для прототипа, HOLD для основного движка**.

Playwright CRX заметно упрощает локаторы, ожидания, ввод, reload и выполнение
пользовательского JavaScript в текущей вкладке. При этом текущий опубликованный
релиз отстает от Chrome и несовместим с Vite 8.

До завершения ручного runtime-теста соблюдаем следующие правила:

1. только `PlaywrightEngine` импортирует `playwright-crx`;
2. core, UI и формат пресета не содержат типов Playwright CRX;
3. версия `playwright-crx` закреплена точно на `0.15.0`;
4. Vite закреплен на `7.3.6` как временное ограничение;
5. проект не начинает реализацию recorder поверх API пакета;
6. при провале runtime-теста выбираем между поддерживаемым fork и собственным
   адаптером на `chrome.debugger`/CDP.

## Ручная проверка перед окончательным решением

1. Выполнить `npm run build`.
2. Открыть `chrome://extensions`, включить Developer mode и загрузить папку
   `dist` через Load unpacked.
3. На обычной HTTP(S)-странице получить активный `tabId` и вызвать команды
   `snapshot`, `reload`, `detach` через временный endpoint.
4. Проверить click, fill, ожидание элемента и выполнение JavaScript.
5. Проверить HTML-модальное окно внутри страницы.
6. Запустить две вкладки одного домена и убедиться, что сессии независимы.
7. Открыть DevTools во время работы и проверить корректную обработку detach.
8. Проверить запрещенные страницы: `chrome://`, Chrome Web Store и PDF viewer.
9. Проверить длинный сценарий и остановку отдельной вкладки.
10. После теста удалить временный endpoint и зафиксировать окончательное ADR.
