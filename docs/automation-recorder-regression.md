# Automation Recorder MVP — ручной regression-checklist

Документ подготовлен для ручного переноса в Qase. Рекомендуемое название suite:
`Automation Recorder MVP — Manual Regression`.

## Общие предусловия suite

1. Установлены Node.js 24 LTS и npm 11.
2. Выполнена команда `npm run verify` без ошибок.
3. Выполнена команда `npm run preview -- --host 127.0.0.1`.
4. Папка `dist` загружена в Chrome как unpacked extension или обновлена через
   `chrome://extensions`.
5. Расширению разрешены `debugger`, `scripting`, `sidePanel`, `storage`, `tabs`,
   `webNavigation` и доступ к HTTP/HTTPS-страницам.
6. Открыта тестовая страница
   `http://localhost:4173/playwright-crx-fixture.html`.
7. Для чистого прогона удалены старые recorder-черновики и тестовые пресеты;
   автоматизации и повторяющиеся циклы не выполняются.

## AR-01. Запись клика и текстового ввода

**Описание:** проверить основной поток записи действий на обычной странице.

**Шаги:**

1. Открыть тестовую страницу и side panel.
2. Нажать `Record`.
3. Ввести `Recorder regression value` в поле `Recorder text`.
4. Нажать `Record test action`.
5. Подождать не менее одной секунды и нажать `Stop recording`.

**Ожидаемый результат:** состояние меняется с `Recording` на `Stopped`; редактор
содержит один `input` и один `click` в фактическом порядке; значение input и
локаторы заполнены; журнал содержит старт, оба действия и остановку записи.

## AR-02. Запись внутри HTML-модального окна

**Описание:** проверить обычное модальное окно внутри DOM страницы, а не
браузерный popup.

**Шаги:**

1. Начать новую запись.
2. Нажать `Open HTML modal`.
3. Ввести `Modal recorder value` в поле `Test value`.
4. Нажать `Save and close`.
5. Остановить запись.

**Ожидаемый результат:** записаны клики открытия и закрытия модального окна, а
также один input с итоговым значением; действия не теряются из-за overlay;
редактор не содержит дубликатов символов или обработчиков.

## AR-03. Reload и продолжение той же записи

**Описание:** проверить продолжение активной сессии после ручной перезагрузки.

**Шаги:**

1. Начать запись и нажать `Record test action`.
2. Перезагрузить вкладку обычной кнопкой Chrome.
3. После загрузки снова нажать `Record test action`.
4. Остановить запись и открыть список шагов.

**Ожидаемый результат:** используется тот же `sessionId`; присутствует ровно
один шаг `reload`; клики до и после reload сохранены в правильном порядке;
захват после загрузки возобновился автоматически.

## AR-04. Редактирование и сохранение portable preset v1

**Описание:** сохранить записанный черновик как запускаемый пресет.

**Шаги:**

1. Использовать черновик из AR-01 или AR-02.
2. Переименовать шаг, выключить один шаг, изменить локатор или значение input.
3. Добавить вручную `wait`, изменить порядок шагов и нажать `Save draft`.
4. Указать имя `Recorder regression preset` и нажать `Create preset`.
5. Экспортировать созданный пресет в JSON.
6. Запустить пресет вручную на тестовой странице.

**Ожидаемый результат:** пресет проходит валидацию, появляется в списке и
запускается существующим AutomationEngine; hostname равен `localhost`, протокол
равен `http`; JSON содержит только portable preset v1 и не содержит `tabId`,
`sessionId`, `documentId`, `recordedEvents`, журнала или состояния Recorder.

## AR-05. Независимые сессии двух вкладок

**Описание:** убедиться, что каждая вкладка имеет собственную запись.

**Шаги:**

1. Открыть тестовую страницу в двух вкладках.
2. В первой вкладке начать запись и заполнить поле значением `First tab`.
3. Во второй вкладке начать запись и нажать `Record test action` два раза.
4. Остановить запись только в первой вкладке.
5. Выполнить ещё одно действие во второй вкладке и остановить её запись.

**Ожидаемый результат:** первая сессия содержит только input первой вкладки;
вторая продолжает запись после Stop первой и содержит три клика; `sessionId`,
счётчики и черновики не смешиваются.

## AR-06. Смена точного hostname во время записи

**Описание:** проверить безопасную остановку при выходе с исходного hostname.

**Шаги:**

1. На `localhost` начать запись и выполнить один клик.
2. В той же вкладке открыть `http://127.0.0.1:4173/playwright-crx-fixture.html`.
3. Открыть side panel и проверить состояние и журнал.

**Ожидаемый результат:** запись остановлена с отдельной причиной
`tab-context-changed`; действие на `localhost` сохранено; события страницы на
`127.0.0.1` не добавлены; журнал объясняет смену hostname и позволяет раскрыть
технические детали.

## AR-07. Закрытие записываемой вкладки

**Описание:** проверить завершение только связанной сессии при закрытии вкладки.

**Шаги:**

1. Открыть две тестовые вкладки и начать запись в обеих.
2. Выполнить по одному различному действию в каждой вкладке.
3. Закрыть первую вкладку.
4. Продолжить действия во второй вкладке и затем остановить её запись.
5. Проверить общий журнал в side panel.

**Ожидаемый результат:** первая сессия завершена с причиной `tab-closed`, её
накопленный черновик не повреждён; вторая сессия продолжает работу; журнал
содержит отдельное понятное сообщение о закрытии первой вкладки.

## AR-08. Восстановление после перезапуска service worker

**Описание:** проверить жизненный цикл Manifest V3 без создания новой сессии.

**Шаги:**

1. Начать запись и выполнить один клик.
2. Закрыть side panel.
3. На `chrome://extensions` открыть DevTools service worker расширения, перейти
   в `Application → Service Workers` и остановить worker, затем закрыть DevTools.
4. Перезагрузить тестовую страницу либо выполнить действие, чтобы Chrome снова
   запустил worker и content script восстановил связь.
5. Выполнить второй клик, открыть side panel и остановить запись.

**Ожидаемый результат:** восстановлена прежняя активная сессия; новая сессия и
дубликаты обработчиков не появились; оба пользовательских действия находятся в
одном черновике.

## AR-09. Автовосстановление message-канала content script

**Описание:** проверить автоматическое внедрение content script в страницу,
открытую до обновления расширения.

**Шаги:**

1. Открыть тестовую страницу до обновления расширения.
2. На `chrome://extensions` нажать `Reload` у расширения, но не перезагружать
   тестовую вкладку.
3. Открыть side panel тестовой вкладки и нажать `Record`.
4. Выполнить клик и ввод, затем остановить запись.

**Ожидаемый результат:** расширение самостоятельно внедряет loader и запускает
запись без reload страницы; клик и input появляются в черновике; в `Run log`
нет ошибки `Receiving end does not exist` и нет дубликатов запуска.

## AR-10. Password и программные события не записываются

**Описание:** проверить фильтрацию недоверенных и чувствительных действий.

**Шаги:**

1. Через DevTools страницы временно добавить `<input type="password" id="pwd">`.
2. Начать запись и вручную ввести значение в это поле.
3. В Console выполнить
   `document.querySelector('[data-recorder-action]').click()`.
4. Вручную нажать ту же кнопку и остановить запись.

**Ожидаемый результат:** значение password и программный клик отсутствуют в
черновике; присутствует только доверенный ручной клик; журнал не раскрывает
введённый пароль.

## AR-11. Ошибка одного события не повреждает черновик

**Описание:** подтвердить сохранность ранее записанных шагов при диагностируемой
ошибке захвата или преобразования.

**Шаги:**

1. Начать запись и выполнить два обычных действия.
2. Воспроизвести диагностическую ошибку content script согласно дефекту или
   тестовой сборке, указанной в Test Run.
3. Остановить запись и открыть редактор шагов.
4. Раскрыть технические детали ошибки в журнале.

**Ожидаемый результат:** два ранее принятых действия остаются в исходном порядке;
ошибочное событие не создаёт частичный шаг; сессию можно остановить и сохранить;
сообщение содержит действие, причину и технические детали.

Если в текущей production-сборке нет воспроизводимого пользовательского способа
вызвать единичную ошибку события, кейс отмечается `Blocked` с ссылкой на
автоматизированную проверку `recorder-diagnostics.test.ts`, а не `Failed`.

## AR-12. Отмена сохранения при конфликте hostname

**Описание:** проверить, что recorder-черновик не уничтожается при отмене
замены активного назначения.

**Шаги:**

1. Убедиться, что для `localhost` уже существует активный пресет.
2. Записать новый сценарий, остановить его и нажать `Create preset`.
3. В предупреждении о конфликте нажать `Cancel`.
4. Проверить сохранённый пресет и recorder-черновик.
5. Повторить Create и подтвердить `Replace assignment`.

**Ожидаемый результат:** после Cancel хранилище не меняется и черновик доступен;
после подтверждения новый пресет активен, прежний сохранён неактивным, а
runtime-черновик удалён только после успешной записи.
