# Требования к первому Release Candidate

Этот документ определяет границы первого стабильного релиза Chrome Automation
Extension, обязательные quality gates и правила принятия решения о выпуске.

## Назначение релиза

Release Candidate предназначен для личной установки как unpacked extension в
Google Chrome на Windows. Публикация в Chrome Web Store, многопользовательский
режим, облачная синхронизация и удалённое управление не входят в этот релиз.

RC считается функционально завершённым только после прохождения автоматических
проверок и ручного regression run на квалификационной версии Chrome.

## Функции, входящие в RC

### Preset Management

- portable preset v1 с JSON Schema и семантической валидацией;
- создание, просмотр, редактирование, дублирование и удаление пресетов;
- ручной импорт и экспорт JSON;
- точная привязка одного активного пресета к одному `hostname`;
- отдельные настройки протоколов `http` и `https`;
- хранение пресетов в `chrome.storage.local`;
- структурированный редактор без обязательного редактирования Steps JSON.

### Automation Runtime

- ручной первый запуск в текущей вкладке;
- независимые сессии разных вкладок;
- шаги `click`, `input`, `wait`, `reload`, `customCode`, `select`, `check`,
  `uncheck` и `pressKey`;
- основной и fallback-локаторы;
- timeout и post-action delay на уровне defaults и отдельного шага;
- обычный, мгновенный и человеческий режимы ввода;
- Stop для одной вкладки и Stop All для всех запусков и будущих повторов;
- остановка текущего прохода и всего repeat-цикла после ошибки шага.

### Automation Scheduling

- повтор только после ручного первого запуска;
- интервал в целых минутах;
- отсчёт интервала после успешного завершения прохода;
- независимые циклы вкладок;
- планирование через `chrome.alarms`;
- восстановление ожидающих циклов после перезапуска service worker;
- остановка цикла при закрытии вкладки или смене точного hostname.

### Automation Recorder

- независимая запись действий по вкладкам;
- запись click, input, select, check, uncheck, pressKey и reload;
- игнорирование программно созданных событий;
- исключение значений `input[type="password"]`;
- продолжение записи после reload на том же hostname;
- остановка при смене hostname или закрытии вкладки;
- редактирование черновика перед созданием portable preset v1.

### Side panel и диагностика

- Dashboard текущего сайта;
- библиотека и редактор пресетов;
- состояния Ready, Running, Waiting, Recording, Stopped, Failed и Unavailable;
- Run log с группировкой по вкладке и запуску;
- фильтры Success, Warning и Error;
- отделение пользовательского сообщения от технической диагностики;
- клавиатурная навигация, видимый focus state и доступные confirmation modal;
- адаптивное отображение side panel от минимальной до расширенной ширины.

## Функции вне границ RC

- публикация и автоматическое обновление через Chrome Web Store;
- синхронизация пресетов между устройствами;
- база данных или внешний backend;
- автоматический запуск сразу после открытия сайта;
- запуск по расписанию без предварительного ручного запуска;
- переключение автоматизации между вкладками и browser popup-окнами;
- выполнение на `chrome://`, `chrome-extension://`, `file://` и других
  привилегированных страницах;
- объединение поддоменов: `example.com`, `www.example.com` и
  `shop.example.com` остаются разными hostname;
- гарантированная работа с iframe и shadow DOM сторонних компонентов;
- запись или специальная обработка кастомных ARIA-checkbox/radio/switch;
- хранение секретов, cookies, токенов и банковских данных.

## Поддерживаемая среда

| Уровень | Версия и среда | Статус |
| --- | --- | --- |
| Минимальный технический уровень | Google Chrome 118+ | Зафиксирован в `minimum_chrome_version`; установка более старой версии запрещена |
| Квалификационная среда RC | Google Chrome 153 Stable, Windows x64 | Обязательный полный автоматический и ручной regression run |
| Другие Stable-версии Chrome 118–152 и новее 153 | Windows x64 | Best effort; не считаются подтверждёнными без отдельного regression run |
| Chrome Beta, Dev и Canary | Любая ОС | Не поддерживаются первым RC |
| Edge и другие Chromium-браузеры | Любая ОС | Не поддерживаются первым RC |
| macOS и Linux | Google Chrome | Не входят в квалификационную матрицу первого RC |

Перед выпуском фактическая полная версия Chrome должна быть записана в отчёте
ручного regression run. Обновление Chrome требует повторной проверки Playwright
attach, reload, HTML-модального окна, Recorder и независимых вкладок.

## Definition of Done

Первый RC готов к выпуску, только если одновременно выполнены все условия:

1. Все функции из раздела «Функции, входящие в RC» реализованы и доступны без
   DevTools.
2. Production-сборка создаётся из чистой установки зависимостей командами
   `npm ci` и `npm run verify`.
3. TypeScript typecheck, unit-, component- и integration-тесты проходят без
   ошибок.
4. Реальный E2E smoke для unpacked extension реализован и проходит; критические
   E2E-сценарии не находятся в `skip` или `todo`.
5. Полный ручной regression-checklist пройден на квалификационной версии Chrome,
   результат сохранён в Qase.
6. Открытых дефектов уровня Critical и High нет.
7. Все открытые Medium-дефекты имеют задокументированный workaround и явное
   решение о принятии риска. Low-дефекты перечислены в release notes.
8. Создание, импорт, экспорт и обновление пресета не повреждают ранее сохранённые
   данные при ошибке.
9. Stop и Stop All проверены на текущем выполнении и ожидающем repeat-таймере.
10. Проверены две независимые вкладки, reload, HTML-модальное окно, custom code и
    восстановление после перезапуска service worker.
11. Run log не содержит password-значения и не ломает ширину side panel длинной
    диагностикой.
12. Версия расширения, changelog, известные ограничения и инструкция установки
    соответствуют собранному артефакту `dist`.

Невыполнение любого пункта 2–6 блокирует выпуск RC.

## Уровни дефектов

### Critical

Дефект блокирует выпуск без исключений:

- расширение не устанавливается, не открывается или постоянно падает;
- потеря или необратимое повреждение сохранённых пресетов;
- неконтролируемое выполнение, которое нельзя остановить через Stop или Stop All;
- автоматизация выполняется в другой вкладке или на другом hostname;
- repeat продолжает запускаться после Stop All или критической ошибки;
- password или другие чувствительные данные попадают в журнал или экспорт;
- custom code выполняется без явного пользовательского действия.

### High

Основной сценарий RC не работает и безопасного workaround нет:

- невозможно создать, сохранить, импортировать, экспортировать или запустить
  валидный пресет;
- Recorder не может завершить сценарий Record → Edit → Save;
- сломаны reload, независимые вкладки, repeat, Stop или Stop All;
- ошибка одной вкладки повреждает либо останавливает другую;
- service worker оставляет постоянное зависшее runtime-состояние;
- существенная accessibility- или layout-проблема делает действие недоступным.

### Medium

Функция работает не полностью, но существует безопасный и понятный workaround:

- некритичный recorder-локатор требует ручного исправления;
- отдельное сообщение журнала недостаточно понятно, но содержит диагностику;
- визуальный дефект не блокирует действие и не скрывает данные;
- деградация производительности на большом наборе пресетов без потери данных.

### Low

Косметический или текстовый дефект без влияния на выполнение:

- небольшое несоответствие отступов, цвета или типографики;
- опечатка, не меняющая смысл сообщения;
- второстепенное улучшение удобства или документации.

Если дефект соответствует нескольким уровням, используется наиболее высокий.

## Обязательные автоматические проверки

### На каждый merge в release-ветку

```powershell
npm ci
npm run verify
```

`npm run verify` обязан успешно выполнить:

- генерацию standalone JSON Schema validator;
- TypeScript typecheck;
- production-сборку Manifest V3;
- unit-тесты домена, портов, адаптеров и форматирования;
- component-тесты side panel;
- integration-тесты Preset Management, Runtime, Scheduling и Recorder.

### Перед созданием RC

```powershell
npm run verify:all
```

- E2E-загрузка папки `dist` как unpacked extension;
- Create/Import → Save → Run;
- Record → Edit → Save → Run;
- reload и HTML-модальное окно;
- repeat после успешного прохода;
- Stop и Stop All;
- две независимые вкладки;
- перезапуск service worker;
- ошибка шага и проверка Run log.

Любой flaky-тест сначала рассматривается как дефект. Простое повторение до
успешного результата не считается прохождением quality gate.

## Обязательные ручные проверки

Ручной regression run в Qase должен включать:

1. установку и обновление unpacked extension;
2. Dashboard для поддерживаемой и запрещённой страницы;
3. CRUD, поиск, фильтры, импорт и экспорт пресетов;
4. выполнение всех типов шагов preset v1;
5. fallback-локаторы, timeout, post-action delay и human input;
6. Record → действия → reload → Stop → Edit → Save → Run;
7. HTML-модальное окно и custom JavaScript;
8. repeat, Running, Waiting, Stop и Stop All;
9. независимые вкладки и смену hostname;
10. восстановление после перезапуска service worker;
11. пользовательские ошибки и раскрываемую техническую диагностику;
12. отсутствие password-значений в черновике, журнале и экспорте;
13. клавиатурную навигацию, modal focus trap и связанные ошибки полей;
14. минимальную и расширенную ширину, длинные имя пресета, hostname и stack trace.

Отчёт должен содержать версию Chrome, commit, версию расширения, дату, итоговые
статусы тестов и ссылки на все найденные дефекты.

## Ограничения Playwright CRX

- `playwright-crx` закреплён на версии `0.15.0` и использует встроенный
  Playwright 1.53.0. Совместимость с каждой новой версией Chrome требует ручной
  runtime-проверки.
- Адаптер использует permission `debugger`. Chrome показывает соответствующее
  предупреждение при установке расширения.
- DevTools или другой debugger-клиент могут отсоединить automation-сессию.
- Frame с URL другого расширения может привести к ошибке вида
  `Cannot access a chrome-extension:// URL of different extension`. Совместимость
  таких страниц не считается гарантированной первым RC.
- Страница `127.0.0.1` и `localhost` являются разными hostname. Известный сценарий
  с защищённым frame на `127.0.0.1` должен быть повторно проверен перед RC.
- Vite закреплён на `7.3.6`: опубликованный пакет Playwright CRX несовместим с
  Vite 8 без upstream-исправления или собственного fork.
- Пакет обращается к browser global `self` при импорте, поэтому реальная
  интеграция проверяется в Chrome, а unit-тесты используют изолированный адаптер.

## Ограничения Manifest V3

- Background является service worker и может быть остановлен Chrome между
  событиями.
- Долгосрочное планирование выполняется только через `chrome.alarms`, а не через
  `setTimeout`.
- Повторный цикл хранит восстанавливаемое runtime-состояние в
  `chrome.storage.session`; оно не входит в portable preset.
- Активная debugger-сессия удерживает service worker начиная с Chrome 118, что и
  определяет минимальную версию manifest.
- Динамический `import()` запрещён в `ServiceWorkerGlobalScope`; background
  bundles должны использовать статические imports.
- In-memory журнал может быть потерян при полном перезапуске service worker;
  portable-пресеты в `chrome.storage.local` при этом сохраняются.
- Обновление unpacked extension прекращает активные выполнения. После обновления
  пользователь обязан повторно открыть страницу и запускать автоматизацию
  вручную.

## Экспериментальные и неподтверждённые возможности

Следующие сценарии не должны описываться как гарантированно поддерживаемые:

| Возможность | Статус RC | Условие перевода в поддерживаемую |
| --- | --- | --- |
| Chrome, отличный от квалификационного Chrome 153 Stable | Неподтверждённая совместимость | Полный automatic и manual regression run на конкретной версии |
| Страницы с frame другого Chrome extension | Экспериментально | Устранена ошибка protected frame и добавлен E2E |
| `127.0.0.1` при наличии protected extension frame | Экспериментально | Стабильный Playwright attach в повторяемом ручном и E2E-тесте |
| Chrome Beta, Dev, Canary, Edge и другие Chromium-браузеры | Не поддерживается | Отдельная квалификационная матрица |
| Автогенерируемые recorder-локаторы для нестандартных компонентов | Best effort | Набор fixture- и E2E-тестов для конкретного типа компонента |

Browser-проверки реализованы в `tests/e2e/extension-flow.spec.ts` и запускаются
командой `npm run test:e2e`. Тесты используют чистый профиль Chromium,
production-папку `dist` и локальные HTTP/HTTPS fixture-страницы.

## Решение о выпуске

Решение оформляется как одно из трёх состояний:

- **GO** — Definition of Done выполнен, Critical/High отсутствуют;
- **CONDITIONAL GO** — только принятые Medium/Low с документированным workaround;
- **NO GO** — не пройден обязательный gate или открыт Critical/High.

По умолчанию любое неоднозначное состояние трактуется как **NO GO** до получения
проверяемого результата.
