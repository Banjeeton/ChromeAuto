# UX-архитектура side panel

## Статус и область решения

Документ задаёт целевую информационную архитектуру side panel и правила
пользовательских сценариев. Он не меняет доменные состояния, формат preset v1
или ответственность background. Side panel остаётся клиентом существующих
runtime-контрактов и отображает полученное состояние без самостоятельного
выполнения автоматизации или записи в Chrome storage.

Весь пользовательский интерфейс и все сообщения остаются на английском языке.
Русский язык используется только в проектной документации.

## Принципы

1. Текущая вкладка и доступное для неё действие понятны без прокрутки.
2. В один момент времени экран имеет одну основную задачу.
3. Run, Record, Stop и Stop recording никогда не обозначаются одной кнопкой.
4. Runtime-состояние вкладки отделено от сохранённого состояния пресета.
5. Ошибка сначала объясняется обычным текстом; stack и технический контекст
   доступны отдельно.
6. Опасное необратимое действие требует явного подтверждения.
7. Цвет дополняет, но не заменяет текстовый статус и доступное имя элемента.

## Информационная архитектура

Side panel состоит из общей оболочки и четырёх основных рабочих разделов.

| Раздел | Назначение | Точка входа | Основной выход |
| --- | --- | --- | --- |
| `Dashboard` | Состояние активной вкладки, ручной Run/Record, Stop и активные вкладки | Открытие side panel или выбор вкладки Dashboard | Presets, Run log или Editor черновика |
| `Presets` | Просмотр и управление сохранёнными пресетами | Основная навигация или действие с Dashboard | Editor, Dashboard |
| `Editor` | Создание, изменение или финализация записанного черновика | New, Edit, Duplicate или Review recording | Сохранение либо возврат к экрану-источнику |
| `Run log` | События выполнения, планировщика и Recorder | Основная навигация или ссылка View details | Dashboard |

`Dashboard`, `Presets` и `Run log` являются постоянными пунктами навигации.
`Editor` является контекстным экраном: он открывается только для конкретного
нового пресета, существующего пресета, дубликата или recorder-черновика. Это не
пустая постоянная вкладка навигации.

Оболочка имеет следующий порядок:

```text
sticky product header
primary navigation: Dashboard | Presets | Run log
optional current-context banner
active section or contextual Editor
global notices
confirmation dialog overlay
```

Header содержит название продукта и доступный текстовый индикатор состояния
расширения. Он не содержит действий конкретного пресета.

## Навигация

- Первое открытие side panel ведёт на `Dashboard`.
- Переход между Dashboard, Presets и Run log не сбрасывает выбранный пресет,
  фильтры списка или накопленный журнал.
- `New preset`, `Edit`, `Duplicate` и `Review recording` открывают Editor и
  запоминают экран-источник.
- `Save` закрывает Editor и возвращает пользователя к источнику. После
  recorder-сценария источником считается Dashboard, после библиотечной операции
  — Presets.
- `Cancel` сразу закрывает неизменённый Editor. При несохранённых изменениях
  открывается подтверждение `Discard unsaved changes?`.
- Browser Back не используется как обязательная часть навигации. На Editor
  всегда есть видимая кнопка `Back`.
- Переключение активной вкладки Chrome обновляет Dashboard и контекст Run log,
  но не закрывает открытый Editor. Для recorder-черновика показывается исходная
  вкладка, чтобы пользователь не принял его за черновик новой активной вкладки.
- Если целевая вкладка закрыта, Editor сохраняет доступный черновик и показывает
  контекстное предупреждение вместо автоматического удаления данных.

## Модель состояния текущей вкладки

Dashboard формирует один итоговый статус активной вкладки. Переходные операции
имеют приоритет над стабильными, чтобы UI не показывал одновременно
противоречивые действия.

| Состояние UI | Значение | Основные действия |
| --- | --- | --- |
| `loading` | Читаются URL, preset, runtime и Recorder | Все изменяющие действия disabled |
| `unsupported` | Активная страница не HTTP/HTTPS или недоступна расширению | Пояснение без Run/Record |
| `empty` | Для hostname нет активного пресета и записи | `Record`, `New preset`, `Browse presets` |
| `ready` | Найден валидный активный пресет | `Run automation`, `Record` |
| `recording` | Recorder принимает действия этой вкладки | `Stop recording` |
| `stopping` | Recorder завершает захват и финализирует черновик | Действия disabled, индикатор процесса |
| `running` | AutomationEngine выполняет текущий проход | `Stop` и `View run log` |
| `waiting` | Успешный проход завершён, назначен repeat timer | `Stop` и время следующего запуска |
| `stopped` | Запись остановлена и доступен recorder-черновик | `Review recording`, `Discard draft` |
| `failed` | Recorder, запуск или проход завершился ошибкой | Краткая причина, `View details`; допустимый Retry определяется доменным статусом |

Если одновременно получены несовместимые снимки, UI выбирает состояние в
порядке `stopping` → `recording` → `running` → `waiting` → `stopped` → `failed`
→ `ready` → `empty` → `unsupported`. Такой конфликт дополнительно записывается
в технический журнал, но side panel не предлагает взаимоисключающие команды.

`failed` не является общей разрешающей командой Retry. После ошибки выполнения
новый Run доступен только после повторной проверки вкладки и пресета. После
ошибки Recorder сначала предлагается открыть сохранённый черновик.

## Основной сценарий Record → Edit → Save → Run

1. На Dashboard пользователь нажимает `Record` для текущей HTTP/HTTPS-вкладки.
2. Dashboard переходит в `recording`, показывает hostname, количество шагов и
   отдельную кнопку `Stop recording`.
3. После Stop background финализирует черновик, а UI переходит в `stopped`.
4. Действие `Review recording` открывает Editor в режиме recorder draft.
5. Пользователь проверяет порядок, локаторы и значения, добавляет wait или
   customCode и исправляет ошибки валидации.
6. `Save as preset` выполняет полную валидацию. Конфликт активного пресета того
   же hostname открывает подтверждение замены назначения.
7. После успешного сохранения runtime-черновик очищается, Dashboard показывает
   созданный пресет в состоянии `ready`.
8. Выполнение начинается только после отдельного ручного действия
   `Run automation`. Сохранение никогда автоматически не запускает пресет.
9. Во время прохода Dashboard показывает `running`; успешный repeat-проход
   переходит в `waiting`, обычный проход — обратно в `ready`.
10. Ошибка переводит карточку в `failed`, останавливает текущий проход и не
    назначает следующий повтор.

Run заблокирован для записываемой вкладки. Запись заблокирована при running или
waiting в этой же вкладке. Другие вкладки сохраняют независимые состояния.

## Running, Waiting, Recording, Stopped и Failed

### Running

Карточка текущего сайта показывает имя пресета, `Running`, текущий шаг при его
наличии и кнопку `Stop`. Прогресс не выражается фиктивным процентом: количество
выполненных шагов можно показывать только при наличии достоверных данных.

### Waiting

Показываются имя пресета, интервал и абсолютное либо относительное время
следующего запуска. `Stop` отменяет ожидающий alarm и весь цикл вкладки.

### Recording

Показываются hostname, текст `Recording`, количество записанных шагов и
`Stop recording`. Run и обычный Stop не подменяют команду остановки Recorder.

### Stopped

Recorder-черновик остаётся runtime-данными до Save или Discard. Основное
действие — `Review recording`; удаление черновика требует подтверждения.

### Failed

Показываются действие и понятная причина. `View details` открывает Run log с
релевантной записью. Технические данные не занимают место на Dashboard.

## Stop и Stop All

- `Stop` расположен на Dashboard внутри карточки `Current site`, рядом с
  текущим runtime-статусом. Он относится только к активной вкладке и видим в
  состояниях running и waiting.
- `Stop recording` расположен в Recorder-блоке той же карточки и не называется
  просто Stop.
- `Stop All` расположен в заголовке блока `Active tabs` на Dashboard. Он не
  дублируется в Presets или Editor и disabled, когда активных выполнений и
  таймеров нет.
- Нажатие `Stop` выполняется сразу: область действия уже ограничена текущей
  вкладкой и явно показана рядом с кнопкой.
- `Stop All` открывает подтверждение с количеством затронутых вкладок и текстом
  о прекращении текущих проходов и будущих повторов.
- Повторные Stop и Stop All безопасны. После ответа background Dashboard сразу
  повторно запрашивает runtime-состояние.

## Состояния экранов

Каждый раздел имеет явные loading, empty и error states. Предыдущие данные не
стираются до успешного ответа, если это не создаёт ложного разрешения действия.

| Раздел | Loading | Empty | Error |
| --- | --- | --- | --- |
| Dashboard | Skeleton текущего сайта и disabled actions | `No automation is assigned to this site.` | Краткая причина и `Retry` |
| Presets | Skeleton списка | `No saved presets yet.` с `New preset` и `Import JSON` | Ошибка чтения и `Retry` без удаления старых данных |
| Editor | Skeleton только при чтении существующего preset/draft | `No steps yet.` с `Add step` | Ошибка возле поля и summary со ссылкой на первый invalid path |
| Run log | Индикатор первичной загрузки | `Automation and recorder events will appear here.` | Ошибка чтения журнала и `Retry`; локальные записи не скрываются |
| Active tabs | Неблокирующее обновление | `No automations are running.` | Последний достоверный список и предупреждение об обновлении |

Busy-состояние относится к конкретной операции: `Saving…`, `Importing…`,
`Starting…`, `Stopping…`. Оно не должно блокировать независимое чтение и
управление другой вкладкой без доменной причины.

## Подтверждения

Подтверждение используется для:

- удаления сохранённого пресета;
- замены существующего пресета при импорте;
- замены активного назначения hostname;
- удаления recorder-черновика;
- выхода из Editor с несохранёнными изменениями;
- Stop All для нескольких вкладок и будущих повторов.

Диалог содержит конкретный объект и последствия действия. Основная безопасная
кнопка получает фокус при открытии; destructive action имеет явный текст
`Delete preset`, `Discard draft`, `Replace assignment` или `Stop all`.
Закрытие Escape и `Cancel` ничего не меняет. Подтверждения не объединяются и не
могут открываться одно поверх другого.

## Ошибки и журнал

Пользовательское сообщение строится как `action + reason`, например
`Unable to run automation: the target tab is no longer available.` Оно не
содержит stack trace. Кнопка или ссылка `Technical details` раскрывает code,
tabId, presetId, stepId, cause и stack, если они доступны.

Dashboard показывает только последнюю релевантную ошибку текущего действия.
Полная история находится в Run log. Ошибка одной вкладки не заменяет статус и
журнал другой вкладки. Password-значения не попадают ни в краткий текст, ни в
технические детали.

## Английские пользовательские тексты

Для одинаковых действий используется один словарь:

| Назначение | Текст UI |
| --- | --- |
| Ручной запуск | `Run automation` |
| Начало записи | `Record` |
| Остановка записи | `Stop recording` |
| Остановка текущей вкладки | `Stop` |
| Остановка всех вкладок | `Stop All` |
| Просмотр черновика | `Review recording` |
| Сохранение черновика | `Save as preset` |
| Отмена изменений | `Cancel` |
| Техническая диагностика | `Technical details` |
| Повторная загрузка | `Retry` |

Нельзя смешивать варианты `automation`, `workflow` и `script` для одного и того
же понятия внутри одного экрана. В пользовательском UI основной термин —
`automation`, а сохранённый контейнер называется `preset`.

## Компонентные границы

Целевая композиция UI:

```text
SidePanelShell
├── ProductHeader
├── PrimaryNavigation
├── DashboardView
│   ├── CurrentSiteCard
│   ├── RecorderSummary
│   └── ActiveTabsCard
├── PresetsView
│   ├── PresetToolbar
│   ├── PresetList
│   └── PresetDetails
├── PresetEditorView
├── RunLogView
├── GlobalNoticeRegion
└── ConfirmationDialog
```

View-компоненты получают готовые view models и отправляют команды через
прикладные hooks/controllers. Они не обращаются напрямую к chrome.storage и не
выполняют бизнес-валидацию самостоятельно. `App` отвечает за композицию,
активный раздел и глобальные подтверждения, но не содержит реализацию всех
feature-экранов.

## Проверка архитектурного решения

- Все четыре раздела имеют назначение, вход и выход.
- Навигация отделена от browser-tab navigation.
- Для текущей вкладки определён один непротиворечивый UI-статус.
- Record → Edit → Save → Run остаётся полностью ручным сценарием.
- Stop, Stop recording и Stop All имеют разные области действия и расположение.
- Loading, empty, error и confirmation states заданы до визуального рефакторинга.
- Все будущие пользовательские тексты создаются на английском языке.
