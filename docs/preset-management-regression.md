# Preset Management MVP — ручной regression-checklist

Документ подготовлен для переноса в Qase. Рекомендуемое название suite:
`Preset Management MVP — Manual Regression`.

## Общие предусловия suite

1. Выполнена команда `npm run build` без ошибок.
2. Папка `dist` загружена в Chrome как unpacked extension или обновлена кнопкой
   `Reload` на странице `chrome://extensions`.
3. Расширению разрешены `debugger`, `sidePanel`, `storage` и `tabs`.
4. Открыты две HTTP/HTTPS-вкладки: `https://example.com/` и
   `https://www.example.com/`.
5. В side panel нет выполняющихся автоматизаций. Тестовые пресеты прошлой
   проверки удалены или экспортированы в резервный файл.

## Автоматизированное покрытие

- репозиторий пресетов: `tests/unit/preset-repository.test.ts` и
  `tests/integration/chrome-storage.test.ts`;
- JSON Schema и семантическая валидация:
  `tests/unit/preset-schema.test.ts`;
- точная hostname-привязка: `tests/unit/site-matcher.test.ts`;
- CRUD, portable import/export и ручной запуск:
  `tests/integration/preset-management-mvp.test.ts`;
- независимые ручные запуски сохранённых пресетов:
  `tests/integration/saved-preset-manual-run.test.ts`.

## PM-01. Пустой список пресетов и обновление состояния

**Описание:** проверить начальное состояние библиотеки пресетов без DevTools.

**Шаги:**

1. Удалить все тестовые пресеты, подтвердив удаление каждого.
2. Закрыть и снова открыть side panel.
3. Нажать `Refresh` в секции `Saved presets`.

**Ожидаемый результат:** отображается понятное пустое состояние; интерфейс не
зависает; в журнале нет необработанной ошибки.

## PM-02. Создание валидного preset v1

**Описание:** создать активный пресет для точного hostname из side panel.

**Шаги:**

1. Открыть `https://example.com/` и нажать `New preset`.
2. Указать имя `Example manual preset`, hostname `example.com`, протокол
   `https`, состояние `Enabled`.
3. Добавить включённый шаг `wait` с условием `timeout` и значением `100` ms.
4. Сохранить пресет.

**Ожидаемый результат:** пресет появляется в списке с правильными именем,
hostname и состоянием; форма закрывается; side panel сообщает об успешном
создании; для текущей вкладки доступен ручной запуск.

## PM-03. Валидация блокирует сохранение

**Описание:** убедиться, что структурно или семантически невалидный пресет не
попадает в хранилище.

**Шаги:**

1. Нажать `New preset`.
2. Оставить имя пустым либо указать hostname `https://example.com/path`.
3. Нажать сохранение.
4. Закрыть редактор и обновить список.

**Ожидаемый результат:** сохранение отклонено; сообщение содержит действие,
причину и путь проблемного поля; ошибочный пресет отсутствует в списке;
технические детали доступны в `Run log`.

## PM-04. Редактирование сохранённого пресета

**Описание:** изменить метаданные, настройки ресурса и последовательность шагов.

**Шаги:**

1. Открыть `Example manual preset` для редактирования.
2. Изменить имя на `Example manual preset updated` и описание.
3. Изменить общий timeout и добавить второй шаг `reload`.
4. Сохранить изменения, закрыть и повторно открыть редактор.

**Ожидаемый результат:** изменения сохранены и повторно отображаются; порядок
шагов не изменён самопроизвольно; `id` и `createdAt` сохранены, `updatedAt`
обновлён в экспортируемом JSON.

## PM-05. Дублирование пресета

**Описание:** создать независимую копию без повреждения исходного пресета.

**Шаги:**

1. Выбрать `Example manual preset updated` и нажать `Duplicate`.
2. Указать hostname `www.example.com` и сохранить копию.
3. Изменить имя и шаг в копии.
4. Повторно открыть исходный пресет.

**Ожидаемый результат:** копия имеет отдельный `id` и временные метки, сохраняет
исходные настройки и шаги на момент дублирования; последующие изменения копии
не меняют оригинал.

## PM-06. Точная привязка к hostname

**Описание:** проверить, что основной домен и поддомен являются разными сайтами.

**Шаги:**

1. Назначить включённый оригинал на `example.com`.
2. Назначить включённую копию на `www.example.com`.
3. Переключаться между вкладками `https://example.com/` и
   `https://www.example.com/`.

**Ожидаемый результат:** в каждой вкладке выбран только её пресет; назначения
не подменяют друг друга; попытка включить второй пресет для того же точного
hostname отклоняется с понятным сообщением.

## PM-07. Подтверждение удаления

**Описание:** проверить отмену и подтверждение опасной операции.

**Шаги:**

1. Нажать `Delete` у копии пресета.
2. В предупреждении нажать `Cancel`.
3. Убедиться, что копия осталась в списке.
4. Снова нажать `Delete`, затем подтвердить удаление.

**Ожидаемый результат:** до подтверждения данные не меняются; после подтверждения
удаляется только выбранная копия; оригинал остаётся доступен; список обновляется
автоматически.

## PM-08. Экспорт portable preset v1

**Описание:** проверить содержимое переносимого JSON-файла.

**Шаги:**

1. Выбрать `Example manual preset updated` и нажать `Export JSON`.
2. Открыть загруженный `*.preset.json` в текстовом редакторе.
3. Проверить основные поля файла.

**Ожидаемый результат:** файл является валидным JSON и содержит
`schemaVersion`, `id`, метаданные, `site`, `automation` и `siteSettings`; в нём
нет активных вкладок, сессий, журнала и другого runtime-состояния.

## PM-09. Импорт и восстановление пресета

**Описание:** восстановить удалённый пресет из экспортированного JSON.

**Шаги:**

1. Удалить экспортированный пресет с подтверждением.
2. Нажать `Import JSON` и выбрать файл из PM-08.
3. Открыть восстановленный пресет в редакторе.

**Ожидаемый результат:** пресет восстановлен с теми же `id`, метаданными,
hostname, настройками и шагами; список обновился автоматически; импорт не
требует DevTools.

## PM-10. Подтверждение перезаписи при импорте

**Описание:** проверить безопасное разрешение конфликта одинакового `id`.

**Шаги:**

1. Изменить имя восстановленного пресета на `Locally changed preset`.
2. Импортировать исходный файл из PM-08.
3. В предупреждении нажать `Cancel` и проверить имя пресета.
4. Повторить импорт и нажать `Replace preset`.

**Ожидаемый результат:** первый импорт не меняет локальный пресет; после явного
подтверждения локальная запись заменяется содержимым файла; предупреждение
показывает имена сохранённого и импортируемого пресетов.

## PM-11. Ошибка импорта не изменяет хранилище

**Описание:** проверить атомарность и диагностику невалидного импорта.

**Шаги:**

1. Создать копию экспортированного файла и удалить из неё поле `name` либо
   повредить JSON-синтаксис.
2. Зафиксировать текущий список и содержимое сохранённого пресета.
3. Импортировать повреждённый файл.
4. Раскрыть `Technical details` у ошибки в `Run log`.

**Ожидаемый результат:** импорт отклонён; сообщение указывает действие и причину,
а для ошибки валидации — JSON-путь; сохранённые пресеты не изменены; в журнале
есть технические детали.

## PM-12. Ручной запуск и независимые вкладки

**Описание:** проверить запуск сохранённого пресета и изоляцию сессий вкладок.

**Шаги:**

1. В пресете для `example.com` временно заменить шаг на `wait` длительностью
   `5000` ms и сохранить.
2. Открыть две вкладки `https://example.com/`.
3. В первой вкладке нажать `Run automation`, затем быстро повторить во второй.
4. Проверить секцию `Running tabs`, дождаться завершения и открыть `Run log`.
5. Перейти на `https://www.example.com/`, для которого активного назначения нет.

**Ожидаемый результат:** запуск происходит только вручную; одновременно видны
две независимые сессии; завершение одной не останавливает другую; в каждой
вкладке журнал содержит успешный шаг; на неназначенном hostname кнопка запуска
недоступна и показано понятное объяснение.
